# Правила разработки

## Основные правила

- Не работать напрямую в ветке main.
- Каждая задача выполняется в отдельной ветке.
- Изменения попадают в main через Pull Request.
- Перед слиянием требуется одобрение хотя бы одного участника.
- Не отправлять в репозиторий пароли, токены и .env-файлы.

## Названия веток

Используем следующие префиксы:

- feature/ — новая функциональность.
- fix/ — исправление ошибок.
- docs/ — документация.
- refactor/ — переработка кода.

Примеры:

feature/12-create-request
feature/user-authentication
fix/request-status
docs/api-description

## Коммиты

Используем формат:

тип: краткое описание на английском

Примеры:

feat: add user registration
fix: correct request status
docs: update README
style: improve request form
refactor: simplify user service

## Pull Request

1. Создать ветку от актуальной main.
2. Выполнить задачу.
3. Зафиксировать изменения коммитами.
4. Отправить ветку на GitHub.
5. Создать Pull Request в main.
6. Дождаться проверки и одобрения.
7. После одобрения выполнить Merge.

## Работа с main

Ветка main содержит стабильную версию проекта.
Прямые изменения запрещены.
